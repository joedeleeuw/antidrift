# Agreed Scope

This document summarizes the active governance clusters and their current owners in the `s-9efw` architecture (one Rust engine on pinned `tsrs`, table-driven `RuleCatalogEntry` contract, direct JS plugin execution in `oxlint`, `eslint`, and `bun lint`, unified 500-line module cap across Rust and TS, and Rust rules configured from Cargo `[workspace.metadata.antidrift]`).

## Included clusters

| Cluster                       | Primary owner            | Package/config home                                                                                      | Notes                                                                                                                                                                                                 |
| ----------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React state shape             | Frontend platform        | `crates/antidrift-rules/src/react_ui`, `tooling/antidrift/src/oxlint-plugin`, `apps/web`, `packages/ui`  | Detect coupled `useState` waterfalls, derived-state effects, and hand-rolled async resource lifecycle state.                                                                                          |
| Type contract shape           | Type platform            | `crates/antidrift-rules`, `tooling/antidrift/src/oxlint-plugin`, `packages/domain`, `packages/contracts` | Detect contract-appeasement projections, structural type forks, nullable positional tuples, unsafe cast chains, and appeasement casts.                                                                |
| Abstraction and file shape    | Architecture             | `policy/agent-guardrails.yaml`, `crates/antidrift-kernel/src/line_caps.rs`, `Cargo.toml`                 | Unified 500-line module cap (warn above 425), 50-line function cap (warn above 40), and 180-line component cap (warn above 150) across Rust and TypeScript; no wrapping functions or one-use helpers. |
| Side effects and boundaries   | Platform                 | `packages/gateways`, `packages/api`, `tooling/antidrift/src/oxlint-config`                               | Prevent direct SDK, DB, env, and raw network access from the wrong layer.                                                                                                                             |
| Error handling                | Reliability              | Oxlint baseline rules, `crates/antidrift-rules/src/directives/no_anemic_errors.rs`, `Cargo.toml`         | Enforce `preserve-caught-error` and `no-anemic-errors` (including silent catch / fallback-to-empty recovery) across TypeScript and Rust.                                                              |
| Test integrity                | Quality                  | Oxlint, `crates/antidrift-rules/src/test_oracle`                                                         | Block `.only`, conditional assertions, placeholder tests, and non-independent test oracles.                                                                                                           |
| Design system                 | Design system            | `packages/ui`, `crates/antidrift-rules/src/react_ui`                                                     | Enforce semantic tokens and UI conventions where project authority is proved.                                                                                                                         |
| Agent ops                     | Developer experience     | `.claude/settings.json`, `.codex/hooks.json`, `tooling/antidrift/src/policy`                             | PreToolUse/PostToolUse/Stop checks for policy artifact protection and deterministic verification.                                                                                                     |
| Agent instructions            | Developer experience     | `policy/agent-guardrails.yaml`, `Cargo.toml`, generated markdown/rules                                   | `policy/agent-guardrails.yaml` and `[workspace.metadata.antidrift]` generate AGENTS, CLAUDE, Codex, and Copilot guidance.                                                                             |
| Semantic architecture drift   | Architecture             | Oxlint boundaries, registries, `[workspace.metadata.antidrift]`                                          | Prevent cross-layer imports, deep imports, cycles, and feature scatter across TypeScript and Rust crates/modules.                                                                                     |
| Domain model drift            | Domain platform          | `policy/registries/domain.yaml`, `packages/domain`, `crates/antidrift-rules/src/contracts_shape`         | Prevent duplicate domain statuses, roles, and redeclared owned unions.                                                                                                                                |
| Contract/schema drift         | API platform             | `packages/contracts`, `packages/api`, `crates/antidrift-rules/src/boundary_schema`                       | Keep handlers, validators, generated types, and consumers aligned.                                                                                                                                    |
| Dependency/supply-chain drift | Platform security        | hooks, `policy/registries/dependencies.yaml`                                                             | New runtime deps and direct SDK imports need approval.                                                                                                                                                |
| Authorization/control drift   | Security                 | `packages/api`, `policy/registries/boundaries.yaml`, `crates/antidrift-rules/src/security_boundaries`    | Routes/actions/jobs require auth, tenant, schema, and ownership checks.                                                                                                                               |
| Observability drift           | Reliability              | hooks, policy research, `packages/api`                                                                   | New async/server boundaries need context and trace/log discipline; no source rule currently owns this cluster.                                                                                        |
| Performance/resource drift    | Performance              | Oxlint, `crates/antidrift-rules/src/lifecycle_async`, `crates/antidrift-rules/src/boundary_schema`       | Oxlint owns broad await-in-loop; the native Rust engine enforces redundant Zod validation, async array methods, unbounded `Promise.all`, fetch timeouts, and query-join reshapes.                     |
| Data lifecycle drift          | Data platform            | migration/fixture policy placeholders                                                                    | Schema/model changes require migration, seed, and fixture alignment.                                                                                                                                  |
| Quality-gate drift            | Developer experience     | hooks, CI, Sonar                                                                                         | Agents must not weaken policy files, lint config, type config, CI, or Sonar.                                                                                                                          |
| MCP/tooling drift             | Platform security        | `policy/registries/mcp.yaml`                                                                             | MCP and tool config changes are executable supply-chain changes.                                                                                                                                      |
| Sonar governance              | Engineering productivity | `sonar-project.properties`, `sonar/`                                                                     | Use Sonar for PR gates, trends, coverage, duplication, cognitive complexity, and imported policy issues.                                                                                              |
