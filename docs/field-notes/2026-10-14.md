## no-appeasement-cast: round 3 measurement and the proof-window fix

The three-root rescan (97 repositories, 162,330 tracked files, 4 parse failures) reports 17,307 casts. The fresh 30-hit sample scores 29/30; the false report is a cast of an unconstrained class type parameter's element, which the rule calls broad by design. Four weak true reports cast un-narrowed values to object types with only `unknown`-valued keys and then `typeof`-test the keys; the fix there is a `typeof` guard, not a decoder.

Labelling the 30 incompletes found three unstable-proof diagnostics that were wrong, not conservative: the disruption window ran to the end of the enclosing loop although the governing test re-executes every iteration, and it counted an early-exit guard's `return` branch. `cast-narrowing-proof.mjs` now ends the window at the cast when the proof lies inside the loop and takes the whole guard statement as the proof point. Only the 86 unstable-proof incompletes can change, so the hit sample stands without a rescan. Two incompletes are over-conservative because the provenance walk follows call arguments of non-generic callees; recorded as a known false negative, not fixed this round.

The landing review (`takeover-reviews/cast-landing`) held on three highs, all fixed in the same pass: the any-depth proof compared only the first tuple slot and no callable signature; the proof window anchored at a whole condition, so an unrelated or truthiness test after a mutation cleared the cast and a call after the predicate inside a compound condition was hidden; an annotated class property followed its initializer's provenance. The window now anchors at the test that establishes the target. One corpus probe flips back to incomplete under the honest anchor (mastra `source-control-sessions.ts:269`, a `RegExp.test` call after the `typeof` test inside the guard). The review's independent read scores incomplete labels 28–30 as conservative rather than correct; labels stay frozen and the docs carry the erratum.
