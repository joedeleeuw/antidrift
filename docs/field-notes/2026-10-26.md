## Dependency ownership resolution

- `no-unlisted-external-imports` now uses TypeScript's configuration and module resolver to distinguish local `paths` and package `imports` from external dependencies. Type-only imports and re-exports accept declared `@types` providers; runtime imports do not. A TypeScript path to a sibling package whose manifest name matches the import still requires the importing package to declare that package, while genuinely local aliases need no npm declaration.
- Package-import targets require owner evidence beyond `isExternalLibraryImport`: TypeScript can mark an external `#` target false. Compare the importing and resolved package owners, and normalize an external `@types` owner back to its runtime package identity before checking runtime declarations. Unresolved configured aliases remain compiler-resolution concerns rather than fabricated npm-package findings.
- Conditional package imports need the mode of the exact usage, not a standalone-resolver default. `createUsageResolver` lazily retains one `SourceFile` per linted file, derives its implied Node format, matches the module literal by position and decoded text, and forwards `getModeForUsageLocation`.
