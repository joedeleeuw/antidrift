## Shape-rule review fixes

The G23 review of the combined shape rules held landing on three findings, and the owner set the fixes. The shared matcher now walks every type reachable from both sides and rejects any or unresolved error types. That includes types behind a shared named type and generic references. TypeScript default-library types are compared through their type arguments only, because their own members contain any, for example `thisArg?: any` on Array. The generated-owner skip accepts only a comment that declares the file generated: `@generated`, a `Code generated ... DO NOT EDIT.` line, or a line that opens with "This file was generated by" or "Generated by". A bare "do not edit" does not count.

A missing dependency is reported where the code uses it, on each import, export, require, dynamic import and import-type specifier, as TypeScript reports unresolved modules. A missing dependency that the package never imports is reported once per package at line 1 of the path-sorted first TypeScript source file of that package. A declared package that is absent from node_modules but resolved by the compiler options counts as found. The augmentation exemption is bound to the owner export the interface merges with. An export that only the linted package declares, such as an interface a module augmentation adds, is not an owner. Samples are now labelled from the checker-resolved owner declaration with its complete members.

The nested any/error rejection removes 240 inline reports and adds none. Fresh samples score 23/24 for the inline rule and 17/24 for the dependency rule, with coincidental library matches counted false. ## Hop engine review fixes

A cross-provider review of the hop engine found five holding defects, and each is fixed. Parameter order alone did not prove that an inline keeps the evaluation sequence, so the engine now orders the body's reads and effects and rejects any call site where an argument would move past a step it does not commute with. Parenthesized and asserted method arguments keep an unbound receiver. A package entry that maps to no source now produces an incomplete-analysis diagnostic at each affected candidate instead of silent suppression. Build inputs come only from the tool's own entry keys in the exported configuration. The measurement population drops all path and category exclusions; only files that declare themselves generated are skipped. A type annotation alone is no longer a contract, and hops without call sites are reported for deletion.

## Correction to the hop engine review fixes

A second review showed that the earlier entry overstated the fixes. Structural property types still let getters reorder, parentheses around a parameter's use still restored a receiver, the build reader ignored spreads, later mutation and unrelated `defineConfig` helpers, the population still skipped files that only say "do not edit", and a directory named `package.json` crashed lint. The engine now treats a member read as effect-free only when the checker resolves it to a class field or object-literal property that is never written and whose receiver binding is never reassigned. Receiver roles are found through wrappers on both sides. Build configuration is evaluated in order, including spreads, and a mutated constant or a `defineConfig` that is not the tool's own export leaves the surface incomplete. A manifest must be a regular file, and any failure inside the analysis becomes an incomplete-analysis diagnostic at the candidate. An exported candidate with no caller in its program is also reported as incomplete, because its consumers are unknown; unexported candidates without callers are still reported as hops. The corpus scan then showed that a program-wide search for writes to each member exhausted the 8 GB heap on Twenty, so a member read now counts as effect-free only when the type system forbids writing it: a readonly class field or a property of an `as const` object literal.
