## 1. The Oxlint Plugin Is the Only Reporter of antidrift Findings (`i-9a21`, `i-5a4o`, lane `oxlint-plugin-host`)

Oxlint owns severity, `overrides` globs, options and disable directives. The launcher runs `oxlint --print-config` first and refuses to run when no `jsPlugins` entry ends with `/oxlint-plugin/index.mjs`. The type-aware helper serves only the typed rules Oxlint requests: default injection, the kind=1 conversion and both env flags are deleted.
- **Equivalence on sudocode** (873 files, program diagnostics suppressed on both paths): hook path 7,576 rows, plugin path 7,576 rows, identical. A first comparison read 89 plugin-side losses in `types/src/*.d.ts` and blamed the governance `ignorePatterns`; both halves were wrong. The engine's `lint_file` refused declaration files (`is_supported_file` excludes `.d.ts`), and the ignore never applied in that comparison because the config file lived outside the repo and Oxlint resolves ignore patterns relative to the config. The refusal is gone; in a real repo the shipped ignore does skip declarations, and a team that wants handwritten declaration packages linted removes the three entries. ## 2. CLI-First Plugin Boundary (`s-9efw` V2, `i-mrww`, `i-66zs`, `i-5n8c`, `i-8x04`)

- **Why LSP `stale-session` glue was dropped:** antidrift runs exclusively as a CLI/CI/agent gate (`antidrift oxlint`, `antidrift verify-session`, `antidrift check-changed`), not inside a long-lived editor language server (`tsrs` programs are `'static` arenas via `Box::leak`, so in-process rebuilds grow RSS ~255 MB per edit on a 360-file program). Removed `crates/antidrift-engine/src/program_inputs.rs`, `FileStamp`, `source_overrides`, `ANTIDRIFT_LINT_RUN`, `antidrift(stale-session)`, and `tooling/antidrift/test/long-lived-host.mjs`.
- **Dual-host JS plugin (`createOnce` + `create`):** Oxlint's plugin loader checks `"createOnce" in rule` at registration time (`node_modules/oxlint/dist/lint.js`) and uses `before()` returning `false` on subsequent rules to skip JS AST initialization (`initAst()`) and traversal on the file. Standard ESLint and Bun ignore `createOnce` and call `rule.create(context)` for every enabled rule before walking `Program()`. Exposing both `createOnce(context)` and `create(context)` on `bridgeRule` and keying `currentFile` by `(context.cwd, context.filename)` supports Oxlint, ESLint, and Bun with one native `lintFile` call per `(cwd, filename)` and zero speed cost in Oxlint.
- **Deterministic binary and preflight resolution:** `resolveAntidriftLinterPath` and `resolveAntidriftNapiAddonPath` now prefer `target/release` over `target/debug` deterministically instead of `mtimeMs` sorting, `resolveAntidriftNativeArtifacts` fails when `linter` and `addon` come from different Cargo profiles, and `verifyConfigRegistersPlugin` forwards only `-c` / `--config` / `--tsconfig` to `oxlint --print-config`.

## 3. Single Owner for Rejected `tsconfig.json` Files, Line-Cap Near Warnings, and CLI Levels (`i-4vsx`, `i-2d77`, `i-9g5u`, `i-7dqg`, `i-2106`)

- **Rejected and broken `tsconfig.json` handling (`i-4vsx`, `i-2d77`):** `crates/antidrift-engine/src/headless_host.rs` (`suppress_program_diagnostics_enabled` and `ProgramFactory::broken_ancestor_tsconfig`) is now the single owner across `headless.rs`, `session.rs`, `runner.rs`, and `derive/mod.rs`. By default (`OXLINT_TSGOLINT_DANGEROUSLY_SUPPRESS_PROGRAM_DIAGNOSTICS` unset), every entry point refuses both unparseable/broken `tsconfig.json` files (instead of silently falling back to the inferred program) and `tsconfig.json` files with compiler options rejected by `tsrs` (such as `baseUrl`), surfacing `Invalid tsconfig (<path>): <help>`. Setting `OXLINT_TSGOLINT_DANGEROUSLY_SUPPRESS_PROGRAM_DIAGNOSTICS=true` suppresses non-fatal program option diagnostics in every entry point alike.
- **Oxlint line-cap near warnings (`i-9g5u`):** `RuleCatalog` in `rule_catalog.rs` resolves `antidrift/max-*-lines-near` to `LineCapTier::Near` and `antidrift/max-*-lines` to `LineCapTier::Over`, `session.rs` matches findings by `LineCapTier::message_id()`, and the Oxlint plugin and governance config register companion warning rule IDs (`antidrift/max-module-lines-near`, `antidrift/max-function-lines-near`, `antidrift/max-component-lines-near`) at `"warn"` while keeping `antidrift/max-*-lines` at `"error"`.
- **Standalone CLI levels and `--deny-warnings` (`i-7dqg`):** `antidrift-linter` accepts `--rule <id>=<error|warn|off>` and `--deny-warnings`, exiting `0` when only warnings remain unless `--deny-warnings` is passed.
- **Root solution `tsconfig.json` in `collectTouchedModuleGraph` (`i-2106`):** `withHeadTree` symlinks `repoRoot/node_modules` into the temporary `git archive` worktree, `readTsconfig` expands project references and workspace child tsconfigs, and `implementationFilesFor` maps `.d.{mts,cts,ts}` entries back to sibling `.{mjs,cjs,js}` source files so `collectTouchedModuleGraph` on the root `tsconfig.json` walks `tooling/antidrift/src/*.mjs`.
