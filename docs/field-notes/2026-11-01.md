# Field Notes — 2026-11-01

## 1. The Oxlint Plugin Is the Only Reporter of antidrift Findings (`i-9a21`, `i-5a4o`, lane `oxlint-plugin-host`)

- **Shape:** `createGovernanceOxlintConfig()` registers `src/oxlint-plugin/index.mjs` through `jsPlugins` and enables every default rule as `antidrift/<rule>: "error"`, taken from the addon's rule listing. Oxlint owns severity, `overrides` globs, options and disable directives. The launcher runs `oxlint --print-config` first and refuses to run when no `jsPlugins` entry ends with `/oxlint-plugin/index.mjs`. The type-aware helper serves only the typed rules Oxlint requests: default injection, the kind=1 conversion and both env flags are deleted.
- **Equivalence on sudocode** (873 files, program diagnostics suppressed on both paths): hook path 7,576 rows, plugin path 7,487. The 89 rows only on the hook path are all in `types/src/*.d.ts`, which the governance `ignorePatterns` exclude; the helper linted every file in a program, the plugin lints only the files Oxlint hands it. No row is plugin-only. Every row is severity error on both.
- **Timing, release builds, median of 3:** plugin 1.73 s, hook 1.05 s. `i-57vj` stays open for the gap (second helper process, bridge). A first measurement read 8.8 s for the hook path because `~/code/antidrift/target/debug` was newer than `target/release` and the launcher picks the newest binary; pin `ANTIDRIFT_LINTER_BIN` and `ANTIDRIFT_NAPI_ADDON` to the release artifacts when timing and check both binaries give the same rows (they did).
- **Consumer smoke:** the packed smoke deletes the installed addon to prove the named failure and must copy it back from `platform-package/`, because every later `antidrift oxlint` run now loads the plugin.

## 2. Long-Lived Hosts Stay Fresh (`i-16yx`)

- **Design** (reimplemented from branch `long-lived-host-freshness` on the current session): the plugin sends `context.sourceCode.text` and the launcher's run id with every request. The engine keeps a `source_overrides` map of buffers that differ from disk, stamps (mtime, length) every project source of a program when it binds without a run id, and rebuilds the whole session when any batch of the requested file is stale. With a run id the stamps are skipped and a batch is validated once per run.
- **Bug found by the first full run:** 874 requests, 738 program builds, 354 s. `build_inferred` binds every configured program of the family as a side effect; those batches were not validated for the run, so the next first touch of such a program read as stale and rebuilt the session. `Batch::bind` now marks the batch validated for the run id. Same run: 1.7 s, identical rows.
- **Proof:** `tooling/antidrift/test/long-lived-host.mjs` drives `oxlint --lsp` over a temp workspace: an open buffer that differs from disk reports from the buffer, a cross-file edit changes the dependent file's findings, and the relayed helper receives the overrides. `rust-parity.mjs` awaits it.
