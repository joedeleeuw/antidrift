## 1. The Oxlint Plugin Is the Only Reporter of antidrift Findings (`i-9a21`, `i-5a4o`, lane `oxlint-plugin-host`)

- **Shape:** `createGovernanceOxlintConfig()` registers `src/oxlint-plugin/index.mjs` through `jsPlugins` and enables every default rule as `antidrift/<rule>: "error"`, taken from the addon's rule listing. Oxlint owns severity, `overrides` globs, options and disable directives. The launcher runs `oxlint --print-config` first and refuses to run when no `jsPlugins` entry ends with `/oxlint-plugin/index.mjs`. The type-aware helper serves only the typed rules Oxlint requests: default injection, the kind=1 conversion and both env flags are deleted.
- **Equivalence on sudocode** (873 files, program diagnostics suppressed on both paths): hook path 7,576 rows, plugin path 7,576 rows, identical. A first comparison read 89 plugin-side losses in `types/src/*.d.ts` and blamed the governance `ignorePatterns`; both halves were wrong. The engine's `lint_file` refused declaration files (`is_supported_file` excludes `.d.ts`), and the ignore never applied in that comparison because the config file lived outside the repo and Oxlint resolves ignore patterns relative to the config. The refusal is gone; in a real repo the shipped ignore does skip declarations, and a team that wants handwritten declaration packages linted removes the three entries. Secondary review of that package shape: `~/tmp.noindex/antidrift-precision-and-options/astra-dts-review.md` (i-2yue).

A first measurement read 8.8 s for the hook path because `~/code/antidrift/target/debug` was newer than `target/release` and the launcher picks the newest binary; pin `ANTIDRIFT_LINTER_BIN` and `ANTIDRIFT_NAPI_ADDON` to the release artifacts when timing and check both binaries give the same rows (they did).
- **Consumer smoke:** the packed smoke deletes the installed addon to prove the named failure and must copy it back from `platform-package/`, because every later `antidrift oxlint` run now loads the plugin.

## 2. CLI-First Plugin Boundary (`s-9efw` V2, `i-mrww`, `i-66zs`, `i-5n8c`, `i-8x04`)

- **Why LSP `stale-session` glue was dropped:** antidrift runs exclusively as a CLI/CI/agent gate (`antidrift oxlint`, `antidrift verify-session`, `antidrift check-changed`), not inside a long-lived editor language server (`tsrs` programs are `'static` arenas via `Box::leak`, so in-process rebuilds grow RSS ~255 MB per edit on a 360-file program). Removed `crates/antidrift-engine/src/program_inputs.rs`, `FileStamp`, `source_overrides`, `ANTIDRIFT_LINT_RUN`, `antidrift(stale-session)`, and `tooling/antidrift/test/long-lived-host.mjs`.
- **Dual-host JS plugin (`createOnce` + `create`):** Oxlint's plugin loader checks `"createOnce" in rule` at registration time (`node_modules/oxlint/dist/lint.js`) and uses `before()` returning `false` on subsequent rules to skip JS AST initialization (`initAst()`) and traversal on the file. Standard ESLint and Bun ignore `createOnce` and call `rule.create(context)` for every enabled rule before walking `Program()`. Exposing both `createOnce(context)` and `create(context)` on `bridgeRule` and keying `currentFile` by `(context.cwd, context.filename)` supports Oxlint, ESLint, and Bun with one native `lintFile` call per `(cwd, filename)` and zero speed cost in Oxlint.
- **Deterministic binary and preflight resolution:** `resolveAntidriftLinterPath` and `resolveAntidriftNapiAddonPath` now prefer `target/release` over `target/debug` deterministically instead of `mtimeMs` sorting, `resolveAntidriftNativeArtifacts` fails when `linter` and `addon` come from different Cargo profiles, and `verifyConfigRegistersPlugin` forwards only `-c` / `--config` / `--tsconfig` to `oxlint --print-config`.
