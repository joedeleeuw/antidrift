# Field Notes — 2026-11-01

## 1. The Oxlint Plugin Is the Only Reporter of antidrift Findings (`i-9a21`, `i-5a4o`, lane `oxlint-plugin-host`)

- **Shape:** `createGovernanceOxlintConfig()` registers `src/oxlint-plugin/index.mjs` through `jsPlugins` and enables every default rule as `antidrift/<rule>: "error"`, taken from the addon's rule listing. Oxlint owns severity, `overrides` globs, options and disable directives. The launcher runs `oxlint --print-config` first and refuses to run when no `jsPlugins` entry ends with `/oxlint-plugin/index.mjs`. The type-aware helper serves only the typed rules Oxlint requests: default injection, the kind=1 conversion and both env flags are deleted.
- **Equivalence on sudocode** (873 files, program diagnostics suppressed on both paths): hook path 7,576 rows, plugin path 7,576 rows, identical. A first comparison read 89 plugin-side losses in `types/src/*.d.ts` and blamed the governance `ignorePatterns`; both halves were wrong. The engine's `lint_file` refused declaration files (`is_supported_file` excludes `.d.ts`), and the ignore never applied in that comparison because the config file lived outside the repo and Oxlint resolves ignore patterns relative to the config. The refusal is gone; in a real repo the shipped ignore does skip declarations, and a team that wants handwritten declaration packages linted removes the three entries. Secondary review of that package shape: `~/tmp.noindex/antidrift-precision-and-options/astra-dts-review.md` (i-2yue).
- **Timing, release builds, median of 3:** plugin 1.51 s, hook 1.05 s. `i-57vj` stays open for the gap (second helper process, bridge). A first measurement read 8.8 s for the hook path because `~/code/antidrift/target/debug` was newer than `target/release` and the launcher picks the newest binary; pin `ANTIDRIFT_LINTER_BIN` and `ANTIDRIFT_NAPI_ADDON` to the release artifacts when timing and check both binaries give the same rows (they did).
- **Consumer smoke:** the packed smoke deletes the installed addon to prove the named failure and must copy it back from `platform-package/`, because every later `antidrift oxlint` run now loads the plugin.

## 2. Long-Lived Hosts: Stale Marker Instead of Rebuilds (`i-16yx`, `i-lexb`)

- **Design tried first** (reimplemented from branch `long-lived-host-freshness`): the plugin sends `context.sourceCode.text` and the launcher's run id with every request; the engine keeps a `source_overrides` map of buffers that differ from disk, stamps (mtime, length) every project source of a program it binds without a run id, and rebuilt the whole session when any batch of the requested file was stale.
- **Bug found by the first full run:** 874 requests, 738 program builds, 354 s. `build_inferred` binds every configured program of the family as a side effect; those batches were not validated for the run, so the next first touch of such a program read as stale and rebuilt the session. `Batch::bind` now marks the batch validated for the run id. Same run: 1.5 s, identical rows.
- **Why rebuilds were removed for editors:** tsrs programs are immortal (`new_program` returns `&'static Program`; hosts, mappers and checker pools are `Box::leak`ed), so every rebuild is retained. Measured with `oxlint --lsp` on sudocode (probe `~/tmp.noindex/antidrift-precision-and-options/lsp-memory/probe.mjs`, RSS of the language-server process tree): 165 MB after initialize, 525 MB after opening one frontend file, then about 255 MB per unsaved edit (3.0 GB at edit 10, 10.7 GB at edit 40), about 90 MB per edit even on the small mcp program; the type-aware helper is not involved (same slope with it off).
- **What ships:** a host without a run id gets one build. When a later request finds the buffer or any stamped source changed, the engine answers `stale` without rebuilding and the plugin reports one `antidrift(stale-session)` finding (plugin-owned rule, on by default in the governance config) telling the developer to restart the language server. CLI runs carry a run id and are unaffected. The process-based engine (next lane, `i-lexb`) brings live rebuilds back by replacing the child process.
- **Proof:** `long-lived-host.mjs` opens a dirty buffer before the first build (reports from the buffer), then edits and a saved dependency change (both report the stale marker, with Oxlint's own typed rule still live), and the relayed helper receives the overrides. `rust-parity.mjs` awaits it.
