# 2026-10-23

## External corpus validation and rule changes

Ran current Antidrift ESLint implementations with installed dependencies against real TypeScript repositories, then compared findings with rule intent. Scratch probes were mirrored outside the Antidrift tree and removed; no production rule was edited.

### Implementation changes supported by real evidence

- `no-identity-schema-transform`: add a direct-identity callback branch for `x => x` and single-return `return x`, before requiring a closed object receiver. Keep the existing exact object-literal reconstruction branch. Neblir's `submitInitiativeBodySchema` is a direct no-op that the current rule misses and the probe catches: https://github.com/martipurull/neblir/blob/9b8b0560d8835ebcd325ef2351b9a9a0108d23c9/src/app/lib/types/initiative.ts#L19. Other direct examples exist in Phoenix, Revoke, and jsrepo, so this is not a one-repo special case. Update the semantic-fact association to include direct identity values and avoid representing an unknown key set as an empty object shape.
- `no-explicit-type-arguments-on-owned-api`: registration resolution must handle object literals containing spread assignments and direct factories that return `queryOptions`/`mutationOptions`. Limit factory support to direct returns, including variable-initializer arrows and one-return function declarations, rather than arbitrary wrappers. Letraz has one spread case and two direct-factory cases at `lib/skill/queries.ts` lines 17, 34, and 51. The unmodified rule reports none; the scratch resolver reports all three: https://github.com/pingSubhajit/letraz/blob/b2d2ae8985cfba30b6b34dcaff40f7be3e5b2cb6/lib/skill/queries.ts#L8-L53.
- `no-underchecked-type-predicate`: distinguish nominal branding from an underchecked object predicate. XAI's `APIError.is` checks a module-owned `Symbol.for` brand and should be evaluated like nominal `instanceof` evidence, not required-field validation: https://github.com/xai-org/xai-sdk-ts/blob/025b8412949941257edc234e11295547dadca853/src/errors.ts#L44-L46. Do not exempt arbitrary string `in` checks or generic brand helpers. The same repository supplies genuine tag-only drift in `isMessage`, `isReasoning`, `isFunctionCall`, and the stream tool-call predicates, so the rule remains useful.

### Confirmed corpus anchors

- `no-nullable-positional-tuple`: Lightdash's `MetricExplorerPartialDateRange = [Date | null, Date | null]` is a real second-repository match and the current rule reports it: https://github.com/lightdash/lightdash/blob/82104de24a053ac9ba7fff7c39f8d5808da5a0d8/packages/common/src/types/metricsExplorer.ts#L32.
- `unknown-input-must-be-decoded` and `no-appeasement-cast`: XAI's stream and model resources validate tags or a few fields and then assert complete generated contracts. These are genuine contract-laundering cases, not merely style findings. `requireRecord` plus a full `ModelList` cast after checking only list/id shape is representative: https://github.com/xai-org/xai-sdk-ts/blob/025b8412949941257edc234e11295547dadca853/src/resources/models.ts#L36-L52.
- `no-schema-validator-transcoding`: Reflet is a clean control. `z.toJSONSchema(generatedDraftSchema)` documents the model output contract in a prompt, while `returns` uses `surveyDraftValidator`; the JSON Schema is not re-derived into a Convex validator: https://github.com/damien-schneider/reflet/blob/2b85fd05cab3bb7453bdce63ffbc89542fad3485/packages/backend/convex/surveys/ai.ts. Seldonframe's build-time tool emission is another documentation-only path.
- Owned-API clean controls: OpenEdX's `useGradebookQuery` forwards inline options and Helm Dashboard's explicit result types use ad-hoc keys rather than registrations. These should stay clean because no owned registration is being bypassed.

### Remaining evidence gaps

- No new positive was found for `no-defensive-shape-probing`, `no-redundant-local-return-type`, or direct Convex JSON-schema validator transcoding. Do not mark those validated by this work.
- `no-appeasement-erasure` does not report XAI's `JSON.parse(text) as unknown`; it reports the literal `return null` branches in the same raw function. Review that literal-absence policy separately rather than treating it as a JSON-parse false positive.

XAI's `mapUsage` deliberately normalizes missing usage fields to zero, and Arroxy deliberately defaults platform detection and schema-error messages. These are useful counterexamples to enabling it globally without classification.

## Ownership and implementation results

- Generic ecosystem rules now live in `typescript-tooling` at `0f9ce5d52ca962471ae1774620f9f77389669bc1`: explicit `any`, `unicorn-js/prefer-switch` with four cases, opt-in Rika property defaults, and opt-in `react-hooks-js/no-deriving-state-in-effects`. Oxlint 1.89 does not provide native `no-restricted-syntax`, `unicorn/prefer-switch`, or `react/react-compiler`; the supported JavaScript-plugin paths are used instead. Optional plugin and rule registration is declared in one case table so they cannot diverge.
- Removed the custom `no-open-dictionary-at-boundary`, `no-else-if-chain`, `no-raw-react-native-touchables`, and `no-host-path-literal` implementations. Their published IDs and replacements remain in `retiredRules`; history was not bulk-deleted. `no-hash-literal` remains separate from host paths: it recognizes a 64-hex value bound to hash/digest/checksum/integrity names, with test and download-metadata exceptions. `no-unresolved-dependency-types` also remains because the compiler does not check manifest-only dependencies or unbuilt workspace entries.
- `no-fallback-to-empty` stays narrower than Rika's catch fallback rule: it targets silent empty array/object returns while allowing catches that read or rethrow the error. Rika rejects catches without a direct throw and default fallback returns, which would also reject intentional handling paths.
- Direct identity transforms now report `x => x` and single-return `return x`, with null shapes rather than a fabricated empty key set. Owned-API registration resolution accepts only proven all-spread objects and direct factories; ordinary property overrides and unproven spreads do not inherit the owner. Nominal brands require the computed property and `in` check to resolve to the same symbol; arbitrary string `in` checks and capability probes do not get an exemption.
- New real anchors: three intended Letraz findings, Neblir's direct identity at line 19, five XAI tag-only predicates with `APIError.is` clean, and Lightdash as the second nullable-tuple repository. They do not by themselves satisfy the multi-repository stable-promotion bar.
- `no-redundant-local-return-type` is not a TypeScript builtin or covered by `no-unnecessary-*`: its nested object-shape and enclosing-contract proof is distinct. Its published name now has an explicit scope in the investigation document: a nested implementation with an enclosing return owner, not every private helper annotation.

## Fallback and remaining evidence

- `enforceNoPropertyDefaultFallbacks` defaults to false and enables only Rika's property-default rule. `propertyDefaultAllowedFiles` uses repository-relative suffix patterns because absolute override paths failed in real consumers. XAI `src/usage.ts` reports nine intentional defaults without an exception and is clean with its declared exception. Arroxy `006473423415851f1e28565b5bcc5c87ee946cdf` reports intentional schema-error/default diagnostics without an exception; its allowed file removes only the Rika findings, leaving the separate `prefer-switch` finding. A global aggressive default is therefore not justified.
- The narrow sentinel rule remains the default. Enabling Rika disables that overlapping ESLint rule, while shared selectors retain template-literal sentinels Rika misses, including optional member reads. Optional calls without a member read stay clean.
- No new positive was established for `no-defensive-shape-probing`, `no-redundant-local-return-type`, or direct Convex JSON-schema validator transcoding. Reflet is a clean control only. `nostr-tools` and `llm-cli`, selected from recently updated `isRecord`-using TypeScript repositories, produced no new findings for the two predicate/probing probes. These are not validation successes to claim as broad proof.
- Anti-slop issue 21 reports an anonymous 568k-line monorepo but no public corpus PR. The other issue links are to anti-slop itself, not an independent corpus. Current public default branches were used for the new anchors instead.
