## `unknown-input-must-be-decoded` bounds were silent in 0.16.0 to 0.18.0

- Review of the post-0.18 work found that `d2272f6` (merged for 0.16.0) changed the trace-depth bound from an incomplete root to `return []`, and added `SUMMARY_ITERATION_INVARIANT` (64) as a `break` that kept an unconverged summary. Both bound events were observed only when `ANTIDRIFT_BOUNDARY_OBSERVATIONS` was set, so input past either bound linted as decoded. The rule doc already described the trace bound as yielding an incomplete root.
- 0.18.1 restores the incomplete root at the trace bound and adds one to a summary that hits the iteration cap. Evidence: an `unknown` parameter under 300 nested conditionals cast to an interface reports `incompleteAnalysis` on 0.18.1 and nothing on 0.18.0; a shallow copy of the same function reports `decodeUnknown` on both. Round-3 controls pass, the four review probes are exact, and the corpus probes are unchanged (inngest, weave, openacme and TanStack silent; Effect `fromJsonSchemaDocument.ts` silent in 8.4 s; acp 27 `decodeUnknown`). Neither bound fires on any corpus probe.
- The boundary-general harness under `~/.local/state/lanes/takeover-reviews/boundary-general-argon/harness/` hard-codes a separate local `antidrift.boundary-general` worktree as the repository, so it measures that worktree whatever the current directory. Copies that read the repository from `ANTIDRIFT_REPO` were used for these numbers; runs of the original scripts from another worktree measure the old lane.
- The 0.16.0 changelog entry said `FIELD_DEPTH` = 3; the shipped value has been 2 since `d2272f6`. Corrected in 0.18.1.

## `unknown-input-must-be-decoded` crashed on 9 private-app client files under 0.18.1

- A private app's 0.15.0 → 0.18.1 bump lints its client with 9 files aborting the rule: 8 `RangeError: Maximum call stack size exceeded` and 1 `TypeError: checker.getTypeArguments is not a function or its return value is not iterable`. An ESLint crash aborts the whole lint group, so the client gate exited 2.
- The overflow is the five-frame cycle `matchedUpstreamRoots → callbackResultRoots → substituteAll → callbackBindings thunk → contextualSources`. A declared callback whose parameter and result share the host call's type parameter (a `useReducer(reducer, initial)` reducer that returns `state`) binds its parameter through the host call, which matches the same callback again, with no `trace` call in between, so neither the `visiting` cut nor `TRACE_DEPTH` sees it. Each contextual binding is now one fixpoint per (parameter, host call argument) through the same entry machinery as declaration summaries (`fixpoint` in `boundary-summaries.mjs`; `summary` is its declaration-keyed case), so re-entry reads the current roots and an unconverged binding gains the `summary-iterations` incomplete root. Review found the first form keyed by (parameter, host call): one callback passed in two positions (`mapBoth("safe", input, identity, identity)`) shared the first position's clean binding and the second position's `unknown` input went unreported; keying by the argument binds each position apart.
- The `TypeError` is `enqueueCompositeChildren` spreading `checker.getTypeArguments(current)` for a type that is not a type reference, where the checker returns `undefined`. It now reads type arguments only under `ObjectFlags.Reference`, as `type-resolution-provenance.mjs` and `ts-rule-kernel.mjs` already do.
- Evidence: a 30-line reducer probe (`useReducer` declared generically, a reducer returning `state`, `render(state)` as the sink) overflows on 0.18.1 and reports only its one `decodeUnknown` cast on this tree. The `mapBoth` probe reports its `as string[]` cast on 0.18.1 and on this tree, as does its twin with two separately declared identity callbacks. The 9 private-app files lint with no crash and no `unknown-input-must-be-decoded` report. Round-3 controls pass with identical messages (83/83, 86 lines), the four review probes are byte-identical, and the corpus probes are unchanged: Effect `fromJsonSchemaDocument.ts` and inngest `runFunction.ts` silent, acp `cli-dogfood-multi-agent.test.ts` the same 59 `decodeUnknown` lines before and after (probe without a tsconfig), openacme `state.test.ts` silent. Harness copies reading `ANTIDRIFT_REPO` are under `~/.local/state/lanes/takeover-reviews/fix-unknown-input-recursion/harness/`.
