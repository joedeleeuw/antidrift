## unknown-input-must-be-decoded: type-directed signature forwarding and declarative semantic boundaries (`boundary-general`)

Comparison across six design families (compiler IR/SSA, abstract interpreter, IFDS/CFL graph reachability, type-system taint, Datalog, and the hybrid finite-domain summary + type-directed signature forwarding + declarative boundary tables) confirmed the owner's diagnosis: the finite root domain (`boundary-summaries.mjs`, `FIELD_DEPTH = 2`) is already the right termination and path-tracking shape; the remaining precision and recall failures are semantic boundary questions and generic call/callback forwarding.

Implemented in `boundary-general` and merge-review follow-ups:

- Type-directed call and callback forwarding (`boundary-plan-roots.mjs`, with `collections` and `nonForwardingOutputs` declared in `boundary-cases.mjs`): `returnedTypeParameters` walks alias type arguments, mapped/indexed-access types, index infos, type-literal properties, and subtype constraints; `matchedUpstreamRoots` binds callback parameters by shared type parameters against the receiver, `this` parameter, non-callable arguments, preceding callable arguments in pipelines, and curried parent call contextual parameters, unpacking collection elements (`Array`, `Set`, `Map`, `Iterable`, etc.) when the source is a collection over `T` and the callback parameter is scalar `T`; `callbackResultRoots` handles point-free higher-order function arguments (`effect.pipe(Effect.provide(layer))`); `callOpaque` separates method-own uninstantiated type parameters from concrete receiver type arguments (`ReadableStreamDefaultReader<Uint8Array>.read()`).
- Semantic boundary and merge-review fixes: ancestor workspace manifest resolution and single non-platform `node_modules` `"dependency"` classification in `boundary-declarations.mjs` (`@sniptt/guards` in monorepo sub-packages); non-callable platform value sources (`HttpRouter.params`) and `+=` string accumulation in `boundary-model.mjs` and `boundary-sources.mjs`; `stripNullish` in `boundary-contracts.mjs` unwraps nullish unions, `NonNullable<T>` intersections (only when extra members are `{}`/`object`), and `Awaited<T>` aliases before checking `TypeParameter`; `demandedBy` in `boundary-sinks.mjs` skips non-deep sub-path roots whose projected field contract in the target is `unknown`; `FIELD_DEPTH` restored from 3 to 2 in `boundary-observations.mjs` (the 2 -> 3 bump was unevidenced and caused $O(b^6)$ `access × path` growth on Effect's `fromJsonSchemaDocument.ts` under its real `packages/effect/tsconfig.json`; `boundary-general`'s 2.85 s timing had passed a non-existent `tsconfig.src.json`).
- Bucket fixes for the r7 sample (bare `return;` ignored in `callbackReturns`, union member projection, shapeless targets, type-parameter claims judged at the use, exported string-union parameters), claims keyed by node (`claimKey`), `trace-depth` bound (256), and `summary-iterations` bound (64) recorded via `observer.boundFired` instead of throwing.
- Corpus role of type/schema libraries: libraries like Effect, Zod, ArkType, and Valibot implement runtime decoders and type-system internals (which legitimately accept `unknown`, inspect runtime tags, and cast internal AST representations). They are termination/boundedness canaries for static bounds (`FIELD_DEPTH`, `TRACE_DEPTH`, `SUMMARY_ITERATION_INVARIANT`), not precision/recall design targets for an application boundary rule.
