## `main` lint lane was masked by a stale packaged binary

- `antidrift oxlint` prefers `tooling/antidrift/dist/bin/antidrift-linter` over `target/release`. On `main` that binary predates HEAD by 30 minutes, so `lint:oxlint` passed there. With HEAD's own release binary (`OXLINT_TSGOLINT_PATH=target/release/antidrift-linter`), `main` fails `no-unsafe-deserialize` at `diff-scoped-adapters.mjs:174` and `rust-parity.mjs:284`.
- Both are fixed on `query-fan-in`. Linter JSON output is now decoded with zod at the `diff-scoped-adapters` boundary. The harness pins `encoding: "buffer"` on the headless `spawnSync`, so the payload is a typed `Buffer` rather than `string | Buffer`.
- The pre-commit hook lints staged files by explicit path. `tooling/antidrift/test/` was outside every tsconfig `include`, so that program had no Node types, and every `JSON.parse` in `rust-parity.mjs` read as `any`. The full-repo lane did not show this. The previous commit only got past the hook on the stale binary. Adding `test/**/*.mjs` to `tooling/antidrift/tsconfig.json` gives the harness real types in both modes.
- When lint results disagree between checkouts, rebuild or delete `dist/bin` before trusting them.
