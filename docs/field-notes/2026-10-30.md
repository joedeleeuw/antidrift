# Field Notes — 2026-10-30

## 1. File Roles Come From the Path Below the Working Directory; Generator Headers Must Lead the File (`i-2wg4`)

- **Gap:** the role predicates (generated, test, spec, fixture, boundary, domain) matched directory names anywhere in the absolute path. The same two-file repo linted under a parent named `build` (Netlify builds in `/opt/build/repo`, Docker images often use `WORKDIR /build`) got zero hop and pass-through findings against four elsewhere; a parent named `tests` or `fixtures` turned every file into a test file.
- **Header gap:** generator markers (`@generated`, `do not edit`, `auto-generated`, `code generated by`) counted anywhere in the first 512 bytes. Over homer, paseo, sudocode, t3code, grok-bot and antidrift, 9 hand-written files were exempt: a field comment (sudocode `executions.ts:13`), a prompt string (grok-bot `user-info.ts:2`), a generator script's own output template (a homer `tmp` vite plugin), JSDoc prose in four vendored alchemy files, and two effect-smol barrels whose generated section follows hand-written imports. Every true generator header seen sits in the leading comments (paseo webview, graphql generator, expo).
- **Change:** kernel `file_role::ProjectPath` (the file path relative to the program's working directory) is the only input the role predicates accept, so no caller can hand them an absolute path; markers count only in the comment trivia before the first statement. `RuleScope` owns the generated skip (`skips_generated`, waived when the rule's options name `files`, and `admits_authored_source`); the eight rules that skip generated files now share it, where only the hop and pass-through rules honoured `files` before. The two inferred-scope predicates and the script-entry check in `no-eager-singleton` also take the project path. Batch cases without `cwd` default to the process working directory instead of the file's own directory, which had reduced every path to its basename.
- **Measured:** all 95 rules over the five TS corpora with the working directory at each repo root, old and new binaries: identical diagnostics (homer 2395, paseo 11013, sudocode 8242, t3code apps 10138, grok-bot 10). No corpus has a role directory above its root, and the newly linted header files carry no findings from the eight rules.
- **Smokes:** two headless probes (a leading generator header silences the hop; generator words in a string or a later comment do not) and a parity smoke that lints the same repo under plain, `build`, `dist`, `gen`, `tests` and `fixtures` parents and asserts identical full output. Parity 95 rules, 137 batch cases, 68 probes; clippy and the Rust self-lint clean.
- **Found, filed:** a debug-build panic (`invalid value for char`) kills one headless chunk in paseo and two in t3code apps on both binaries. Root cause: a lone-surrogate literal (`"a\uD83D"`) yields cooked text that is not valid UTF-8, and `no-raw-foreground-opacity` walks it; release builds are in undefined behaviour (`i-4il5`, P1). Three rules still keep local path tables (`i-812r`).

## 3. One Kernel Table Owns Every Line Cap; TypeScript Gets Native Module, Function and Component Rules (`i-1abz`)

- **Owner:** `crates/antidrift-kernel/src/line_caps.rs` declares one row per unit (Rust file, module, function, component): rule id, line count (non-blank for Rust, physical for TypeScript), warn tier, ceiling and split hint. `rust/max-file-lines` reads its row and its constants are gone; `antidrift/max-module-lines`, `antidrift/max-function-lines` and `antidrift/max-component-lines` lower the other three in `crates/antidrift-rules/src/directives/line_caps.rs`.
- **Thresholds:** the landed policy rows from `a2cefcd` win over spec `s-4mhg` §7.1 (68/80, 100/120, 340/400): function 40/50, component 150/180, module 1,200/1,500.
- **Severity:** batch and the native runner report `nearCap` as warn through `line_caps::tiered_severity`. Under oxlint every antidrift diagnostic is an error, because the headless protocol carries no severity and injected rules are absent from the oxlint config. So the warn tier blocks in governed repos whether or not `denyWarnings` is set, which matches the Rust self-lint under `--deny-warnings`.
- **Scope:** a function counts from its first token to its closing brace, blank and comment lines included. Immediately invoked functions and describe-style suite callbacks (`describe`, `suite`, `context` and their `each`/`only`/`skip`/`skipIf` chains) are exempt containers; `it` and `test` bodies count. A component is a function with a PascalCase React name (memo and forwardRef aware) whose own body contains JSX, and it gets the component cap instead of the function cap. There is no generated-name skip: as with the old `max-lines`, only registry-declared generated paths are excluded, so renaming a file to `*.generated.ts` cannot dodge a cap.
- **One owner per size:** the governance config turns off oxlint `max-lines` and `max-lines-per-function`. The consumer smoke expects `antidrift/max-module-lines` on the same nine oversized files, and its precedence proof moved to `no-nested-ternary` because injected native rules have no oxlint off-switch. That smoke caught a hole: the headless runner dropped every absolute path containing `/fixtures/` when it injected defaults, so with oxlint's caps retired `src/fixtures/helper.ts` had no cap at all, and any repository under a directory named `fixtures` lost every native rule. The skip is deleted; the kernel's file roles own the fixture concept on the project-relative path. Corpus blast radius: paseo's six fixture sources gain one `max-function-lines` and three `no-unsafe-deserialize` findings, t3code apps' 191 gain two `no-unsafe-deserialize` findings, and both also report tsconfig resolution errors from the unbuilt clones; homer and grok-bot have no fixture sources and sudocode's one reports nothing.
- **Policy binding:** the parity smoke reads warnAt and max for all four units from `policy/agent-guardrails.yaml` and checks each at warnAt, warnAt+1, max and max+1: batch for TypeScript, the Rust CLI with and without `--deny-warnings`, and one explicitly requested near-cap function headlessly. Setting the function warnAt to 39 fails it. Proving the injected defaults through `antidrift oxlint` is `i-7fvr`.

## 4. Lone Surrogates, the File-Role Table and Redundant Decodes (`i-4il5`, `i-812r`)

- **Lone surrogates:** tsrs stores a `"\uD83D"` escape as WTF-8 inside a `&'static str` (tsrs_core `encode_js_string_rune`), so any char-decoding read of cooked literal text was undefined behaviour in release and aborted debug builds; a paseo test file aborted the linter. The kernel now owns three readers: `cooked_text` (exact, `None` when undecodable), `cooked_text_lossy` (classification, U+FFFD) and `decodable_text` (checker-owned strings), and `clippy.toml` bans every raw cooked-text accessor. The codex (gpt-6.1-sol) review found two fail-open highs the abort fix had opened: `no-sql-string-concat` stopped reporting SQL whose static fragment held a lone surrogate, and derive wrote checker property names and literal types into `wire.ts` as invalid UTF-8. Both are fixed and re-reviewed; the parity smoke asserts the SQL findings, plants two derive cases and strictly decodes every generated file. Follow-ups: `i-4xtg`, `i-2srx`, `i-1950` (an import specifier with a lone surrogate still aborts inside tsrs module resolution).
- **File roles:** one `FileRole` table replaces the kernel test, boundary and domain predicates and four rule-local path tables. Folding `no-default-export-in-domain` into the kernel Domain vocabulary widened it (homer's Convex `schema.ts`), so that rule keeps its own matcher and `i-5ngq` replaces it with Oxlint's `import/no-default-export`. An astra (gpt-6-astra, xhigh) review of the direction agreed with declared roles over keyword guesses and reordered the work: mandatory rule scope plus an explain command (`i-92md`), then declared layers with a role field (`i-3mxo`), then the Rust rule move (`i-66ch`); it also found that antidrift's own `architecture.yaml` describes a template app, not its crates.
- **Corpus flake:** two all-rules runs over five corpora differed only by four `no-structural-type-fork` findings dropped in the second run of paseo and t3code; rerunning the affected chunks twice per binary reported them every time (`i-20y4`). Diff corpus rows with `LC_ALL=C` sort and diff; `comm` under the default locale misreports the JS-sorted files.
- **Redundant decodes:** `errorFromUnknown(cause)` on a value already typed `AtomicFileWriteError` erases the type through `unknown` and can never take its other branch. No rule catches it (typescript-eslint and Oxlint `no-unnecessary-type-conversion` know only built-in conversions). A whole-program scan of the five corpora found the signature-only condition noisy (homer 208 hits, mostly format checks such as `z.uuid().parse(string)`), three real cases once the helper's only guard is a type test (`i-qab2`), and zero re-decodes by the same decoder for any library, so recognizing decoders by signature (`i-37xj`) is a cleanup, not new coverage.
- **Warn tier under Oxlint:** a 1,242-line test file stopped a commit at the 1,200 watermark; `i-9g5u` carries the launch decision.
