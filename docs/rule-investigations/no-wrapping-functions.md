# no-wrapping-functions

Status: implemented as two stages; the typed stage is an error in the typed ESLint preset and the Oxlint preset does not run the syntax stage.

## Two-stage design (October 13, 2026)

Stage 1 is the portable syntax rule (`src/oxlint-plugin/portable/no-wrapping-functions.js`). It now also treats composed calls, template literals and object or array literals built from forwarded values as candidates, as the owner's ruling states. Stage 2 is the typed ESLint rule (`src/eslint-plugin/rules/no-wrapping-functions.js`). For each candidate it inlines the body at every reference in memory, deletes the function and its import specifiers, adds the imports the body needs, re-checks only the edited files with the TypeScript checker, and reports only verified hops. A candidate is kept as an owner when an overload, merged declaration, ambient declaration or default export needs the function, when any reference is not a direct call, when the package entry points export it, or when it binds a literal and is called from two or more modules. A type annotation alone is not a capability, and a hop without call sites is reported for deletion. Hazards reject the candidate: a parameter used other than exactly once in order, spread or extra call arguments, a call type that changes, a free name that resolves to another binding at a call site, any diagnostic the edit introduces, and any call site whose evaluation sequence the inline would change. The sequence check orders the body's steps as the program evaluates them; a property read counts as a read only when the checker resolves it to a readonly class field or a property of an `as const` object literal (never an accessor or interface member), so the type system forbids writing it, and its receiver binding is never reassigned; calls, accessors, structural members, spreads and non-primitive template conversions count as effects. An argument may move past a preceding body step only when one of the two is immutable (a literal, or a binding that is const, a function, class or enum, or never reassigned) or both are reads. Receivers stay unbound through parentheses, `as`, `satisfies` and non-null wrappers around both the argument and the parameter's use. Each package entry maps to a source through the package's `build` script: the entry path itself, `tsc` outputs of the configs it names, or the inputs of the build tool it runs, read only from the tool's own entry keys in the configuration the file exports. Build configuration is evaluated as the tool receives it: spreads and later properties apply in order, a constant that is used other than by reading makes it unknown, and `defineConfig` counts only when imported from the tool's own package. The rule reports an incomplete-analysis diagnostic that names the cause when the engine cannot decide: a name in the body does not resolve, the body's evaluation order is not modelled, call sites overlap so the edits cannot be planned, an exported candidate's entry maps to no source, the manifest cannot be read, an exported candidate has no caller in its program, or the analysis itself fails. `typescript-engine.js` owns every program, checker and language-service call; `package-entry-points.js` reads package manifests and build declarations; `hop-inline-verification.js` holds the owner table and the edit plan. The raw TypeScript checker and language service are sufficient, so no ts-morph dependency is added.

The Oxlint preset turns the syntax stage off: Oxlint has no types and sees one file, so its report would restore the false positives the typed stage rejects.

## Policy decision

On September 8, 2026 the owner explicitly chose a style policy against named delegation wrappers, asked for loud enforcement, and rejected a default-off rule. The owner decides the convention; the detector identifies the prohibited shape. A diagnostic does not claim that deleting a function is mechanically safe.

This is one general rule covering function declarations and named arrow/function expressions, including exports. It is not Convex-specific and does not require an explicit return annotation. Caller count matters only for the owner ruling on bound literals: a function that binds a literal and is called from two or more modules is kept. Anonymous inline callbacks do not add a named layer and are outside the rule.

The initial advisory argued against broad enforcement because a wrapper can name a domain concept or a future extension point. The owner explicitly rejected those as sufficient justifications for the extra function. That supersedes the initial default-off proposal. The advisory's concrete concerns about callback timing, receivers and public APIs remain relevant to remediation. The retired `no-thin-typed-factory-wrapper` stays retired: its typed-return claim is a different rule.

## What reports

A named synchronous, non-generator function whose body is one returned call, one call statement, or an arrow call expression is a candidate. The callee is an identifier or a noncomputed member path, and it may itself be a call (composed calls count). Arguments are references, literals, templates, object and array literals built from forwarded values, spreads of those, or nested calls of the same shape. Parameter defaults and destructuring, generic specialization, type predicates and optional calls are outside the candidate stage. The typed stage then decides: a candidate reports only when its inline verifies at every reference.

```ts
export function useMachines() {
  return useConvexQuery(convexApi.machines.list, {});
}

export const loadItem = (id) => owner.load(id);

function closeItem(id) {
  owner.close(id);
}
```

All three report when the typed stage verifies them. A name, an export, or changing a declaration into a named arrow does not exempt the wrapper. A reference that is not a direct call (a callback, a registered listener, a value stored in an object) keeps the function, because it is passed by identity. An exported function with no caller in the program gets an incomplete-analysis diagnostic instead of a hop report, because its consumers outside the program are unknown.

These stay clean, because they compute, branch or are anonymous:

```ts
button.onClick(() => owner.close(id));
const area = (radius) => Math.PI * radius ** 2;
function readRequired(id) {
  const item = owner.load(id);
  if (!item) throw new Error("Missing item");
  return item;
}
```

Class and object methods are outside this initial function-declaration/variable scope. The rule has no autofix. Inline the existing call at its callers while preserving argument order, timing, receiver and hook position. When an API requires a callback, preserve both its signature and stable identity: direct callback substitution is valid only when the existing owner already has the exact compatible signature and receiver behavior. For example, replace `const subscribe = (onStoreChange) => subscribeToConsent(onStoreChange)` with `useSyncExternalStore(subscribeToConsent, getSnapshot)` only when `subscribeToConsent` is the compatible owner; this keeps a module-level callback identity instead of creating a new adapter on every render. Do not replace a required stable adapter with an inline arrow, `.bind`, or a fake statement just to silence the diagnostic. If argument adaptation, receiver binding, hook position, or a named callback identity is required, retain the boundary through the repository's existing documented exception process; the shared rule stays enabled.

## Ecosystem and runtime ownership

ESLint's [no-useless-call](https://eslint.org/docs/latest/rules/no-useless-call) checks redundant `.call()` and `.apply()`. Unicorn's [prefer-native-coercion-functions](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/main/docs/rules/prefer-native-coercion-functions.md) targets native coercion functions. The existing Antidrift `no-trivial-property-helpers` targets named property access and fallback helpers. None catches general named delegation.

The Oxlint plugin exports the syntax stage and the ESLint plugin exports the typed stage under the same rule name. The Oxlint preset registers it off; the typed ESLint preset registers it at error.
