# no-inline-structural-type-at-use-site

Reuse an existing object type instead of repeating its properties in a boundary parameter.

The rule checks parameters of exported functions, public methods of exported classes, and methods of exported or returned objects. Component props and callback type declarations remain outside scope.

A matching type must be identical at every depth: the same property names, optional, readonly and visibility flags, index signatures and call signatures. No type reachable from either side may be any or an unresolved error type, including types reached through a shared named type or a generic reference; The walk follows member and signature types of default-library types too, with a visited set per type and polarity. An error type is rejected anywhere. `any` is rejected wherever a value reaches the code that holds the shape: property, index value, return and predicate types, and parameters of callbacks the code supplies. That rejects `Function`, `JSON`, `Promise` (its rejection reason) and `RegExp` (replacer arguments), and keeps `Date`, `Array`, `Map`, `Set` and `ReadonlyArray`. A parameter typed `any` that the shape only accepts does not reject it. Signature type-parameter defaults and constraints are walked. The matcher is `tooling/antidrift/src/semantic-adapters/shape-identity.mjs`, shared with `no-restated-dependency-type`. The inline type needs at least three members. The rule also reports a repeated inline shape within one package. The message names the existing declaration and its repository-relative file and line.

The rule searches source files in the TypeScript program. The search excludes node_modules, TypeScript library files, explicitly identified fixture files, declaration files whose output paths TypeScript maps from sources in the program, and files whose leading comment declares them generated: a line that opens with an `@generated` tag, a `Code generated ... DO NOT EDIT.` line, or a line that opens with "This file was generated by" or "Generated by". A bare "do not edit", or `@generated` mentioned in prose, does not count. A package is the nearest directory with a package.json file.

The rule requires TypeScript parser services. Missing services produce an error.
