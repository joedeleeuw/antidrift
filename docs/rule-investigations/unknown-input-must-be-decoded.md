# unknown-input-must-be-decoded

The shared `boundary-model.mjs` adapter owns I/O provenance, signature decoding and local value flow. `boundary-cases.mjs` declares every root source, contextual framework shape, decoder form and exclusion. Platform rows name their actual library/module and declaration symbol. Framework rows use contextual request shapes; their package names are examples, not matching filters. The rule's factory interface is unchanged.

`trace(expression)` returns provenance, including decoded and pending Result evidence; `decode(call)` classifies the checker signature; `unchecked(expression, target)` checks the receiving contract; `argumentType(call, index)` projects rest and tuple parameters onto each argument. The model does not treat dependency any/unknown declarations as outside input. A dependency operation must receive traced I/O through its declared generic argument, callback argument or method receiver, or remain unresolved.

Roots are platform I/O and contextual framework request fields, plus an exported first-party function's explicit unknown parameter. JSON.parse opens a root only when its string comes from I/O or an exported string entry parameter. Local JSON and local serialization consequently have no fresh I/O root; there is no constant-input, round-trip, filename or expect-matcher exemption. Defaulted and uninstantiated type parameters are not roots. Node global fetch inherits body reader declarations from undici-types, explicitly named in the table.

A first-party decoder exempts its own unknown subject only when every returned payload is proved narrowed or decoded. Return annotations and cast-only implementations provide no exemption at definitions or calls. Decoder recognition uses declared signatures accepting unknown/any and returning typed output, a discriminated Result, or a predicate/assertion. A generic input instantiated as any does not turn a carrier into a decoder. Checker narrowing establishes branch dominance and survives callbacks when TypeScript preserves it. A discarded decode does not validate the original binding. Metadata projected from a decoded result does not create a new dependency root.

The rule checks casts, annotated declarations, assignments, typed call arguments and explicitly typed returns. It follows aliases, assignment histories, destructuring, property access, await, generic argument/return relationships and receiving callbacks. It does not implement general heap analysis, arbitrary interprocedural argument propagation, or Effect service acquisition without contextual input provenance. A missing root is unresolved, not proof of trust. External decoder signatures establish the output contract. First-party proof is conservative: direct decoder returns, checker-narrowed projections and object fields, primitive property guards, and terminal assertion guards are supported; arbitrary control-flow and heap proofs remain unresolved. Missing parser services still produce an error. There is no automatic fix.

The earlier assertion-only implementation regressed. It reported 19,903 hits with 0/20 precision on the fresh corpus. The earlier rule reported 4,238 hits there; its preceding October 12 sample scored 10/20. These samples use different populations. The owner now requires the provenance checks described above.

## Claim-path model: course-review rework on October 14, 2026

The course review of the provenance model (`takeover-reviews/course-boundary`) found that its whole-root `claimed` and `projected` booleans erased first claims and hid violations, that its proof accepted annotations, that spreads, constrained generics and `any` receivers lost provenance, that an unsupported flow vanished into an empty result instead of an incomplete diagnostic, and that the double-cast exclusion was applied at the assertion only. The model was reworked rather than discarded; the I/O root table, declaration ownership and bound-library signature recognition stay.

The owner is now split at the declaration/proof seam: `boundary-cases.mjs` declares the case space (platform sources, framework request shapes, decoder forms with their carrier contracts, exclusions), `boundary-declarations.mjs` resolves declaration facts (package ownership, platform sources, decoder signatures and their first-party proof, carrier paths, inspection assertions), `boundary-syntax.mjs` holds the syntactic helpers, and `boundary-model.mjs` traces value flow and decides each sink. The sink table lives in the model (`uncheckedAt`, `uncheckedArgument`), so the rule and the evidence tooling ask the same owner the same question.

A root now carries the contract of the first claim it passed through (`claim`): a typed declaration, parameter, return annotation, `as` cast or type argument inside the linted program, projected onto the field it flows into. A later use is covered when that claim proves the demanded contract, so the cast or declaration that first asserted the type is the one report and the downstream reads are silent; a safe string use (`const candidate: string = localStorage.getItem(...)`) is not a claim, and the later `as Mode` still reports. A claim whose contract cannot be resolved (an unresolved import) makes the first use an `incompleteAnalysis` diagnostic naming the unresolved contract and covers the uses behind it. Object literals carry per-field roots and spread precedence; a use demands only the fields of its receiving contract, so `{key:'owned', body:input}` assigned to `{key:string}` is silent while its `body` assertion reports. Proof is decided per path: the receiving contract's field type against the field initializer's flow type, with the cast proof's any-depth matcher, and an opaque root needs real narrowing from its declared type (a `typeof` guard, an `Array.isArray` test, a predicate) rather than an inferred or asserted type, because a generic sink's argument infers its type from the sink itself.

Decoders: a first-party decoder is proved on every normal return through the subject (guarded projections after an inspection cast to unknown-valued keys, deserialized string input through `JSON.parse`, assignments to a `let`), with `null`/`undefined` failure literals beside at least one proved return, and an annotated binding never certifies its initializer. A validation carrier (Zod `safeParse`, Effect `Either`) is safe while it stays intact; extracting its payload needs a checked success branch and an assertion is not that check; decoded domain unions are decoded values, not carriers. Platform string methods are projections whose output type is trusted (`opaque: false`) while their provenance is kept for a later narrow cast; an `any`-receiver call keeps its receiver's roots and claim; an unresolved global receiver (`process` without Node types) is incomplete naming the declaration; a root inside a nested callback takes every assignment of its declaring function; a variable whose cross-callback mutation cannot be ordered stays incomplete rather than empty. Inline double casts belong to `no-unsafe-cast-chain` and are excluded once in the model, so parent declarations, arguments and returns do not re-report them.

Controls (outside the repository, not precision labels): the round-3 control file with its expectations corrected (double casts silent, the cast-only helper reported at its cast and silent at the call), the platform control for the course review's H1–H4 shapes, the real-package decoder control (Effect domain union silent, unchecked Zod success cast reported), and the course review's corpus probes (Shire `server.ts`, toolpa `gateway-request.ts`, inspir `guest-chat`, acp `webhook-hook` and kndl `client.ts` silent; agentdock `useSettings.ts:74` and `Dashboard.tsx:903` reported; Zenith `chat.ts:121` the single incomplete first report; Chaski `core.ts:25` incomplete; acp `gh-bridge` spans kept; jaeyeonling and lootlog complete without a crash). No diagnostic span is reported twice.

Measurement tooling (`round4/evidence`): the baseline is the real `574c614` model and rule extracted from git, not the earlier hand-copied `before-model.mjs`; a scan receipt records its status, the files each completed batch scanned and the failed batch when a child dies, so a partial scan is never presented as complete; rule crashes are captured per rule and file so a baseline crash does not hide the final rule's coverage; recall attributes a site only through the diagnostic span or the causal roots of the model's own decision, and function proximity is recorded as a non-causal association that counts for nothing.

The full scan exposed one termination defect in the claim-path model: `trace` copied its visited set at every branch (each object property, assignment, call argument and conditional arm), so a file that reassigns one `let` through a local helper many times (`apps/cli/test/state.test.ts` in sandydasari-openacme, 276 lines) re-traced the same subexpressions along every path and did not finish in four minutes. The model now memoizes `trace` per expression and per callback-binding map inside one program; the per-path visited set still cuts cycles, and a second visit returns the first visit's roots instead of re-tracing them. That file now lints in 1.4 s. The 24 repositories scanned before the fix produced identical final-mode hits on the probed files (agentdock `useSettings.ts` and `Dashboard.tsx`, claude-for-you `messages-log-postgres.ts`, chaski `core.ts`, zenith `chat.ts`, toolpa, acp, inspir) under the scan's own project configs, and the scan was restarted from scratch on the memoized source; the pre-fix receipts are kept beside the evidence as `prefix-scan-aborted/`, not counted.

The restarted scan exposed a second termination defect: `typeParameters` walked the return type of every call signature it met and relied on a visited set, but a recursive generic builder (TanStack `createServerFn().middleware([...])`) returns a fresh instantiation at each level, so the set never repeated and the walk overflowed the stack on two test files. The walk now stops `RETURNED_FUNCTION_DEPTH` (8) returned functions deep; the probes, the round-3 controls and the platform and decoder controls are unchanged, and both files lint without reports.
