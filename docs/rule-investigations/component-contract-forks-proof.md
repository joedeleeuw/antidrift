# Component contract forks: real-artifact acceptance

Issue #39 extends the existing [Homer reproduction harness](../../tooling/antidrift/test/reproduce-homer.mjs) rather than adding a unit test or a hand-written fixture. Run it from the Antidrift repository root under its supported Node runtime:

```sh
node tooling/antidrift/test/reproduce-homer.mjs "$HOMER_CHECKOUT" --owned-projections-only
```

`HOMER_CHECKOUT` is an explicit, read-only local Homer checkout containing both pinned revisions and already-installed dependencies. No host path is baked into the command, and the harness neither fetches nor installs. It archives each revision into temporary directories and links the corresponding existing dependency directories. The supplied checkout remains unchanged.

Omit `--owned-projections-only` to run the same owner assertions followed by the previously reviewed portable/native corpus and JSON repair proof. The scoped flag selects a real-repository acceptance slice; it does not change any assertions in the default command.

## Why the packed consumer gate remains portable

The existing [consumer monorepo gate](../../tooling/antidrift/test/consumer-monorepo.mjs) creates and installs an isolated synthetic consumer of the packed artifact. It does not own a Homer repository path. Making that ordinary package gate depend on a particular host checkout, network clone, or mandatory environment variable would make it non-portable. The explicit archive command above is a separate corpus acceptance input. The consumer gate remains responsible for shipped exports/configuration and its existing accepted-generated-owner, imported-owner, and unaccepted-package checks.

The historic portable corpus predates `no-wrapping-functions`. The default harness continues asserting the reviewed counts for every currently supported rule in the pinned review (51 rules); it explicitly reports the current unreviewed rule under `unreviewedCustom` instead of inventing an expected count or serializing its absent configuration as a `null` rule option.

## Semantic ownership correction after independent review

The umbrella failure was treating representation as authority: printed type names as contract equality, any reference syntax as owner derivation, export labels as competing owners, and listener order as authority to suppress another configured rule. The correction keeps the existing two policy modes explicit rather than weakening accepted declaration policy:

- Configured accepted whole named contracts still block exact redeclarations without requiring a value-use witness. Shared checker equivalence now establishes the type relation (including private-member incompatibility and modifiers); printed fingerprints remain fact presentation. Anonymous/partial projections still require the contextual owner-use proof.
- Exact checker identity retains all accepted owner paths, rather than making equivalent exports ambiguous or picking a label. Owner-derived references are resolved through actual types/declarations; unrelated aliases cannot erase handwritten portions of a contract. Indexed owner fields and nested `Pick`/`Omit` remain valid.
- Each rule reports under its own ESLint severity and directives. Overlap is coalesced within a rule, never across rule identities. Enabling both explicitly configured owner rules can therefore produce two diagnostics; this intentionally replaces the earlier global single-diagnostic promise.

Scoped strict in-memory full-Program/Linter experiments established the warning/error and disable-directive controls, generated alias stability, unrelated primitive alias stability, nominal private-class rejection, preserved configured named positives, fully derived and partially handwritten wrappers, nested `Pick`/`Omit`, and the exhaustive bridge positive. All retained probes had zero TypeScript diagnostics; an intermediate nested-`Pick` regression was corrected by following owner property declarations, not by adding a utility-name exemption. These are review evidence, not new unit tests or durable corpus coverage. No existing test or fixture was edited or removed by this correction.

Exact checker identity preserves opaque shared types in the named declaration policy (including the same `any`/`unknown` type), but nonidentical intersection, callable, constructable, indexed, or accessor surfaces abstain: mutual assignability plus equal data properties cannot establish their exact contracts. This is a deliberate conservative limit, not a claim that such contracts are equivalent. Recursive equality closes only an already checked type pair; branch-local recursion state does not leak across speculative union alternatives.

No literal circular wiring between production rules and tests was found: the collector imports no fixtures and contains no Homer identifier allowlist. The validation defect is weaker independence, not demonstrated circularity: the ordinary required packed positive exercises named declaration matching, while the contextual collector's real positive lives in the optional archive run. Removing the collector was not executed as a complete CI ablation, so no full-gate survival claim is made. Required durable contextual coverage and complete archived Program health remain explicit gaps rather than being concealed by temporary synthetic probes.

The existing packed consumer remains the required declaration-policy/portability positive. The archive pair remains the contextual projection oracle, not a required CI gate. No gate wiring or expected archive counts were changed. Required release and archive acceptance of this correction must be reported separately from the prior validation below. Full Program construction/source-file counts alone never certify semantic health; the archived dependencies are linked from the current checkout, and the helper does not enforce a clean full-Program diagnostic set.
