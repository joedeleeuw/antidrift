# no-restated-dependency-type

Import an object type that a declared dependency already exports instead of restating it.

The rule checks first-party interfaces and type literals with at least three members. Dependencies are the keys of `dependencies`, `devDependencies` and `peerDependencies` in the nearest package.json, workspace packages included. A dependency is found in node_modules or, failing that, through the linted program's module resolution when the resolved package's manifest has the dependency's name. Public entry points are the package root and every subpath in its `exports` map, with wildcard subpaths expanded to matching TypeScript files. Owners are interfaces and type aliases with at least three properties exported from those entries, directly or through exported namespaces. Classes are not owners, and neither is an export whose declarations all sit in the linted package, such as an interface a module augmentation adds. A match must be identical at every depth through `tooling/antidrift/src/semantic-adapters/shape-identity.mjs`, the matcher shared with `no-inline-structural-type-at-use-site`; no reachable type may be any or an unresolved error type. An interface that merges into the owner export itself, checked by symbol identity, does not report.

Entry points missing from the linted program are added to one second program that reuses the linted program's source files.

A declared dependency that neither lookup finds is a coverage gap. That fact belongs to the manifest, so the preset lints `package.json` with ESLint's JSON language (`@eslint/json`) and the rule reports it on the dependency's key, once per declaring package. The rule also reports it on the module specifier of each import, export, require, dynamic import and import type of that package, as TypeScript and eslint-plugin-import report unresolved modules. A workspace or linked dependency, whose real path lies outside node_modules, is also a gap on its key when a declared types entry (`types`, `typings` or a `types` export condition) does not resolve, as with an unbuilt `dist`. An installed registry artifact, whose real path lies under node_modules (the pnpm store or a plain install), is immutable: a dangling types target there means the package publishes no owners at that subpath, so the key is not reported. effect@3.22.1's `./.index` entry is such a case. An import of an installed dependency that binds no resolvable module, including such a dangling subpath or an untyped JavaScript package, is reported at its specifier. A consumer that spreads `createConfig()` into `eslint.config.mjs` gets the `package.json` block automatically; `eslint .` lints every `package.json` the configured ignores leave in place.

## Measurement after the second review round on October 14, 2026

The rule is default-off. The shipped lint population of 39 installed oss-corpus repositories, with 2,497 `package.json` files linted, gives 219 restatement reports in 18 repositories. Coverage gaps: 4,499 missing-package reports on manifest keys, 3,961 at import sites, 2,768 unresolved workspace-entry reports on manifest keys, and 52,339 unresolved imports of installed packages, most of them imports of unbuilt workspace packages such as `twenty-shared/utils`. The 20 agent-written repositories give 85 restatement reports and 8, 18, 2 and 6 gap reports of those kinds. twentyhq-twenty finishes with an 8 GB heap at 7.0 GiB peak RSS.

A hit-weighted sample capped at 3 per repository, seed 2026101407, excluding every earlier sampled location, holds 24 restatement reports from 12 repositories. Source review labels 14 true, 6 false and 4 coincidental matches with an unrelated library. The false reports are three vendored mongodb or bson declaration copies, two data-migration snapshots and one type-test expectation specimen. The published score counts coincidences false: 14/24 = 58.3%, below the 70% bar, so the rule is default-off. Counting coincidences true gives 18/24. Label file `labels-no-restated-dependency-type.tsv`, SHA256 `5324756c7e2518d971d8fcb997b6223be73b2f71f85010b11ac10230e89cb7e2`.

Agreement with the dependency corpus detector on `cases-real.jsonl`: 62 of 65 positives and 0 of 47 negatives; 50 of 52 without the coincidental and error-shaped categories. This is agreement, not recall.
