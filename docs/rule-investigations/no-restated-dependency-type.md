# no-restated-dependency-type

Import an object type that a declared dependency already exports instead of restating it.

The rule checks first-party interfaces and type literals with at least three members. Dependencies are the keys of `dependencies`, `devDependencies` and `peerDependencies` in the nearest package.json, workspace packages included. A dependency is found in node_modules or, failing that, through the linted program's module resolution when the resolved package's manifest has the dependency's name. Public entry points are the package root and every subpath in its `exports` map, with wildcard subpaths expanded to matching TypeScript files. Owners are interfaces and type aliases with at least three properties exported from those entries, directly or through exported namespaces. Classes are not owners, and neither is an export whose declarations all sit in the linted package, such as an interface a module augmentation adds. A match must be identical at every depth through `tooling/antidrift/src/semantic-adapters/shape-identity.mjs`, the matcher shared with `no-inline-structural-type-at-use-site` and its four comparison rules: an error type makes the comparison undecided, reported as `undecided` at the declaration when no owner matches; `any` compared directly never matches; the same type, or the same generic reference or alias with equal type arguments, matches without comparing what it contains; everything else is compared structurally. An interface that merges into the owner export itself, checked by symbol identity, does not report.

Entry points missing from the linted program are added to one second program that reuses the linted program's source files.

A declared dependency or entry this rule cannot inventory is a coverage gap that `no-unresolved-dependency-types` reports; that rule runs whether or not this one is enabled. See `docs/rule-investigations/no-unresolved-dependency-types.md`.
